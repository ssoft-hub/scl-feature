# implicit::indirect

Исполнитель с размещением значения в куче и семантикой копирования при записи
(copy-on-write), на основе интрузивного, поддерживающего аллокатор управляющего
блока.

- Заголовок: `#include <scl/feature/executor/implicit/indirect.h>`
- Объявление: `template <typename Value, typename Allocator = std::allocator<Value>, typename Counter = std::atomic<std::size_t>> class indirect;`
- Пространство имён: `scl::feature::implicit`

---

## Описание

`implicit::indirect<Value>` хранит значение в куче в одном интрузивном
управляющем блоке — счётчик ссылок размещается рядом со значением. Копирование
исполнителя (а значит и копирование `wrapper`, который его использует) разделяет
этот блок; копирование значения не происходит. Значение клонируется лениво при
первом обращении через **неконстантный** исполнитель, пока оно ещё разделяется
(счётчик ссылок больше единицы). Обращение через константный исполнитель никогда
не клонирует.

В сравнении с реализацией на `std::shared_ptr` это оставляет исполнителя шириной
**в один указатель** (при пустом аллокаторе), выполняет **одну** аллокацию на
каждое отдельное значение и позволяет выбрать тип счётчика ссылок: `std::atomic`
для потокобезопасного счёта (по умолчанию) или обычное целое для однопоточного
использования без накладных расходов на атомарность.

Клонирование выполняет `guard()`. Он срабатывает перед любым изменяющим
обращением: `execute()` вызывает его на пути диспетчеризации рефлексии, а утилиты
блокировки (`wrapper_guard`, `value_lock`) — на фазе захвата. Сам `access()` —
чистый аксессор и никогда не клонирует; copy-on-write работает за счёт того, что
диспетчеризация разрешает `access()` *внутри* `execute()`, уже после отсоединения
в `guard()`, поэтому любой рефлексивный вызов метода работает с объектом, которым
не владеет ни одна другая копия.

`execute(self, func, args...)` вызывает `guard()`, а затем `func(args...)`. Логика
copy-on-write сосредоточена в `guard()`; `access()` сам по себе не клонирует, поэтому
прямой неконстантный `access()` в обход `execute()`/`guard()` возвращает ссылку на
всё ещё разделяемую аллокацию — вызовите сначала `guard()` (или обращайтесь через
рефлексивный вызов), чтобы отсоединить.

> **Замечание.** Исполнитель не может определить, изменяет ли *вызываемый метод*
> значение; он видит лишь cv-квалификацию обёртки в точке вызова. Поэтому любое
> обращение через **неконстантную** обёртку клонирует разделяемое значение, даже
> для метода только для чтения. Чтобы прочитать без клонирования, обращайтесь
> через константную обёртку (или константную ссылку).

> **Предупреждение.** Клонирование выполняется копирующим конструктором `Value`.
> Полиморфный `Value`, хранящий производный объект, будет срезан; `Value` должен
> быть конкретным хранимым типом. Для значимо-полиморфного хранения используйте
> `implicit::polymorphic`.

`indirect` не предоставляется для `volatile`-квалифицированных исполнителей — у
счётчика ссылок нет volatile-квалифицированных операций, поэтому volatile
перегрузки рефлексии отбрасываются, а не становятся некорректными.

## Параметры шаблона

| Параметр | По умолчанию | Назначение |
|----------|--------------|------------|
| `Value` | — | хранимый тип значения |
| `Allocator` | `std::allocator<Value>` | аллокатор управляющего блока; перепривязывается внутри |
| `Counter` | `std::atomic<std::size_t>` | тип счётчика ссылок; `std::atomic` для потокобезопасного счёта |

### Выбор пользовательского аллокатора

`wrapper` принимает исполнителя как шаблон с одним параметром. Свяжите свой
аллокатор через alias с одним параметром:

```cpp
template <typename T>
using my_indirect = scl::feature::implicit::indirect<T, my_allocator<T>>;

scl::wrapper<Foo, my_indirect> w{ /* ... */ };
```

Экземпляр аллокатора с состоянием можно передать при конструировании через
перегрузку с `std::allocator_arg`.

## Интерфейс

```cpp
template <typename Value,
          typename Allocator = std::allocator<Value>,
          typename Counter   = std::atomic<std::size_t>>
class indirect
{
public:
    using value_type     = Value;
    using allocator_type = Allocator;
    using counter_type   = Counter;

    // Конструирует хранимое значение на месте в куче (аллокатор по умолчанию).
    template <typename... Args>
    explicit indirect(Args &&... args);

    // Конструирует хранимое значение на месте с заданным экземпляром аллокатора.
    template <typename... Args>
    explicit indirect(std::allocator_arg_t, allocator_type const & allocator, Args &&... args);

    // Конструкторы и присваивания (копирование/перемещение). Копирование разделяет
    // блок (увеличивает счётчик); перемещение передаёт владение. Volatile
    // квалификации исключены ограничениями.
    indirect(indirect cv_ref other);              // копирующие категории разделяют, &&-категория крадёт
    indirect & operator=(indirect cv_ref other);

    // Отсоединяет (клонирует) разделяемое значение. Срабатывает перед любым
    // изменяющим обращением: вызывается из execute() на пути диспетчеризации
    // и утилитами блокировки.
    template <typename Self>
    static void guard(Self && self);

    // Возвращает ссылку на хранимое значение, сохраняя cv-ref квалификаторы.
    // Чистый аксессор — не клонирует; отсоединение выполняют guard()/execute().
    template <typename Self>
    static decltype(auto) access(Self && self);

    // Вызывает func(args...) и возвращает результат.
    template <typename Self, typename Func, typename... Args>
    static decltype(auto) execute(Self && self, Func && func, Args &&... args);
};
```

## Примеры

### В качестве исполнителя обёртки

```cpp
#include <scl/feature/wrapper.h>
#include <scl/feature/executor/implicit/indirect.h>

scl::wrapper<std::vector<int>, scl::feature::implicit::indirect> a{1, 2, 3};
auto b = a;          // разделяет аллокацию — без копирования значения
b->push_back(4);     // b клонируется лениво; a по-прежнему хранит {1, 2, 3}
```

### Прямое использование

```cpp
#include <scl/feature/executor/implicit/indirect.h>

using Indirect = scl::feature::implicit::indirect<int>;

Indirect a{42};
Indirect b{a};                                 // разделяет аллокацию

Indirect::guard(a);                            // отсоединить разделяемое значение (copy-on-write)
Indirect::access(a) = 7;                         // теперь изменяем собственную копию a
// Indirect::access(std::as_const(b)) по-прежнему == 42 (b не затронут)
```

### Однопоточный счётчик

```cpp
// Без накладных расходов на атомарность, если обёртка не пересекает потоки.
using Indirect = scl::feature::implicit::indirect<int, std::allocator<int>, std::size_t>;
```
