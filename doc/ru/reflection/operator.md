# Макросы рефлексии операторов

Создают перегрузки-посредники для операторов, перенаправляя вызовы от обёртки к
хранимому объекту через исполнитель.

- Заголовок: `#include <scl/feature/reflection/operator.h>`

---

## Семейства макросов

| Макрос | Отражает | Назначение |
|--------|----------|------------|
| `SCL_REFLECT_BINARY_OPERATOR(op, name)` | `w op x`, `x op w`, `w1 op w2` | симметричные бинарные операторы (`+`, `<`, …) |
| `SCL_REFLECT_EQUALITY_OPERATOR(op, name)` | `w op x`, `x op w` с результатом типа `bool` | `==`, `!=` |
| `SCL_REFLECT_PREFIX_UNARY_OPERATOR(op, name)` | `op w` | префиксные унарные (`-`, `~`, `++`, …) |
| `SCL_REFLECT_POSTFIX_UNARY_OPERATOR(op, name)` | `w op` | постфиксные унарные (`++`, `--`) |
| `SCL_REFLECT_SUBSCRIPT_OPERATOR(op, name)` | `w[i]` | `operator[]`, в том числе для указателя |
| `SCL_REFLECT_MEMBER_BINARY_OPERATOR(op, name)` | `w op x` | операторы, обязанные быть членами класса (`=`, `*=`, …) |
| `SCL_REFLECT_MEMBER_PREFIX_UNARY_OPERATOR(op, name)` | `op w` | префиксные операторы, обязанные быть членами (`->`, `&`, `*`) |
| `SCL_REFLECT_MEMBER_POSTFIX_UNARY_OPERATOR(op, name)` | `w op` | постфиксные операторы, обязанные быть членами |
| `SCL_REFLECT_FRIEND_BINARY_OPERATOR(op, name)` | `w op x` только через ADL | бинарные, доступные только через ADL |
| `SCL_REFLECT_FRIEND_PREFIX_UNARY_OPERATOR(op, name)` | `op w` только через ADL | префиксные, доступные только через ADL |
| `SCL_REFLECT_FRIEND_POSTFIX_UNARY_OPERATOR(op, name)` | `w op` только через ADL | постфиксные, доступные только через ADL |
| `SCL_REFLECT_OPERATOR_WITH_ARGUMENTS(op, name)` | `w(...)` | `()`, `->*` (со стороны значения — только член класса) |

`SCL_REFLECT_TYPE` должен быть объявлен в том же теле класса до любого макроса операторов.

---

## Что отражается

Отражённый оператор применяет операцию к обёрнутому значению в виде выражения —
`value op arg`, `op value`, `value[index]`, — а не вызывает заранее выбранную
функцию-член. Затем обычное разрешение перегрузки для этого выражения выбирает
собственный оператор значения:

- **оператор-член** значения, если он определён (оператор-член имеет приоритет над
  свободным); либо
- **свободный или встроенный** оператор в противном случае.

Так как встроенные операторы фундаментальных и указательных типов вычисляются тем же
выражением, они также отражаются: `wrapper<int>{} + 5`, `-w`, `w1 * w2` и
`wrapper<int*>{arr}[2]` работают. cv-ref-квалификация обёртки передаётся значению,
поэтому нужная перегрузка значения (`&`, `const &`, …) выбирается в соответствии с
квалификацией обёртки.

Аргумент бинарного или индексного оператора считывается на один уровень глубже с
захватом исполнителя: аргумент-обёртка (`w1 op w2`) разворачивается один раз, а
`guard()` и `unguard()` вызываются вокруг чтения; обычный аргумент передаётся без
изменений.

## Направление (бинарные операторы)

| Выражение | Выбранная перегрузка | Отражает |
|-----------|----------------------|----------|
| `w op x` (обёртка слева) | оператор-член левой обёртки | `value op x` |
| `x op w` (обёртка справа, `x` — не обёртка) | обратная скрытая дружественная функция | `x op value` |
| `w1 op w2` (обе — обёртки) | оператор-член левой обёртки | `value1 op value2` |

Обратная дружественная функция исключается, когда левый операнд сам является обёрткой
(`is_wrapper_v`), поэтому `w1 op w2` разрешается в перегрузку левой обёртки без
неоднозначности.

```cpp
template <typename Wrapper, typename Executor>
class scl::feature::reflect<Wrapper, Executor, MyValue>
{
    SCL_REFLECT_TYPE(Wrapper, Executor)
    SCL_REFLECT_BINARY_OPERATOR(+, plus)        // w + x, x + w, w1 + w2
    SCL_REFLECT_EQUALITY_OPERATOR(==, equal_to) // w == x, x == w (bool)
};
```

У унарных операторов один операнд, поэтому обратного случая нет.
`SCL_REFLECT_EQUALITY_OPERATOR` возвращает `bool`: этого требует C++20, чтобы обратный
кандидат сравнения `x == w` формировался из оператора-члена обёртки.

## Путь вычисления (переопределение в исполнителе или `execute`)

| Путь | Условие | Что вызывается | Тип результата |
|------|---------|----------------|----------------|
| переопределение в исполнителе | определён `Executor::operator_<name>(exec, args...)` | этот статический член напрямую, с неизменёнными операндами | тип результата переопределения |
| через `execute()` | переопределение отсутствует | `Executor::execute(exec, callable, exec, args...)`; вызываемый объект применяет оператор к значению, полученному внутри `execute()` | тип отражённого выражения |

Механизм переопределения действует только для формы «обёртка слева» и для унарной
формы. У обратной дружественной функции пути переопределения нет, но она также проходит
через `Executor::execute`, поэтому сквозная логика исполнителя работает в обе стороны.
Каждая перегрузка объявлена как `decltype(auto)` и возвращает результат дословно, без
повторного оборачивания.

## Только члены класса (`SCL_REFLECT_MEMBER_*`)

Стандарт C++ ([over.oper]) требует, чтобы `operator=`, `operator->`, `operator()`,
`operator[]` и составные присваивания были нестатическими функциями-членами самой
обёртки; со стороны *значения* при этом допустим свободный или встроенный оператор.
`operator&` и `operator*` также оставлены только членами: свободный запасной вариант
для `&` превратил бы `&wrapper` в отражение `&value` и перехватил бы получение адреса
самой обёртки.

```cpp
SCL_REFLECT_MEMBER_BINARY_OPERATOR(+=, plus_assign)
SCL_REFLECT_MEMBER_PREFIX_UNARY_OPERATOR(->, arrow)
```

`reflect_operators` (базовый класс `scl::wrapper` по умолчанию) использует их для `*=`,
`/=`, `%=`, `+=`, `-=`, `<<=`, `>>=`, `&=`, `|=`, `^=`, `->`, `&`, `*`.

---

## Только дружественные функции (`SCL_REFLECT_FRIEND_*`)

Отражают **свободный** оператор значения как скрытую дружественную функцию обёртки: она
находится через ADL (`w op x`), но не через явный вызов члена `w.operator op(...)`. Не
сочетайте с макросом `SCL_REFLECT_*_OPERATOR` для того же `name`: оба создают одни и те
же вспомогательные объявления в классе, что приводит к повторному определению.

## Примеры

### Симметричное сравнение

```cpp
struct Length { bool operator==(Length) const &; };

template <typename W, typename E>
class scl::feature::reflect<W, E, Length>
{
    SCL_REFLECT_TYPE(W, E)
    SCL_REFLECT_EQUALITY_OPERATOR(==, equal_to)
};

scl::wrapper<Length> a, b;
bool r1 = (a == b);          // value == value (обе — обёртки)
bool r2 = (a == Length{});   // value == x     (обёртка слева)
bool r3 = (Length{} == a);   // x == value     (обратная дружественная функция)
```

### Фундаментальный тип значения

```cpp
scl::wrapper<int> n{40};
int  s = n + 2;   // 42 — встроенный int + int, отражён
bool c = n < 50;  // встроенное сравнение
int  m = -n;      // встроенное отрицание

scl::wrapper<int *> p{arr};
int e = p[2];     // встроенное индексирование указателя
```

### Составное присваивание, обязанное быть членом класса

```cpp
scl::wrapper<int> c{0};
c += 42;   // отражает int += int через собственный operator+= обёртки
```

> Обычный `=` — особый случай. У `scl::wrapper` копирующее, перемещающее и
> преобразующее присваивание — это собственный оператор обёртки (он обязан подавить
> неявно удалённые копирующее и перемещающее присваивания; см.
> [wrapper](../wrapper/wrapper.md)), который скрывает любой отражённый `operator=`.
