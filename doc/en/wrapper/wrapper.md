# wrapper

Composable proxy that stores a value and delegates all method calls through
an executor template.

- Header: `#include <scl/feature/wrapper.h>`
- Declaration: `template <typename Value, template <typename> class Executor> class wrapper;`
- Namespace: `scl::feature::detail` (aliased as `scl::wrapper<Value, Executor>`)

---

## Description

`scl::wrapper<Value, Executor>` holds a `Value` inside an `Executor<Value>` and
exposes the value's interface by forwarding every call through the executor.
The executor controls how the value is stored and accessed — it can add
cross-cutting behaviour such as thread safety, copy-on-write semantics, or
deferred construction without modifying `Value`.

The `Executor` template parameter must satisfy `concepts::executor`: it must
provide static `access()` and `execute()` methods for all three primary value
categories (`E&`, `E&&`, `E const&`).

`wrapper` inherits from `scl::feature::reflect<wrapper, Executor<Value>, wrapper>`
which wires in all proxy methods reflected for the held value type.

## Member types

| Type | Description |
|------|-------------|
| `value_type` | The stored value type (`Value`) |
| `executor_type` | The executor instantiation (`Executor<Value>`) |

## Constructors

```cpp
// Direct construction — forwards all arguments to the executor.
template <typename... Args>
constexpr explicit wrapper(Args &&... args);

// Copy/move from the same wrapper type (all 8 cv-ref qualifications).
// Generated by SCL_WRAPPER_CONSTRUCTOR_FOR_SELF.
constexpr wrapper(wrapper cv_ref other);

// Converting construction from any other wrapper type.
// Generated by SCL_WRAPPER_CONSTRUCTOR_FOR_OTHER.
// Uses wrapper_constructor_resolver for strategy-based construction.
template <typename Other>
constexpr wrapper(Other && other);
```

## Assignment operators

An executor carries no assignment operator of its own (the [executor](../type_traits/executor.md)
concept requires it to be neither copy- nor move-assignable), so a wrapper never
assigns one executor to another. `w = x` instead **reflects assignment through the
executor**, with the same two-path dispatch as every other reflected operator (see
[operator reflection](../reflection/operator.md)): an executor
`operator_assign(self, rhs)` override is used when present (receiving the raw
operand — the same convention as the `operator_<name>` overrides), otherwise the
wrapped value is assigned through `execute()` as the expression `access(self) = source`.

```cpp
// Copy/move/converting assignment from the same wrapper type (all 8 cv-ref
// qualifications of the source). Generated by SCL_WRAPPER_ASSIGNMENT_FOR_SELF.
// These are user-declared copy/move assignment operators: declaring them
// suppresses the implicitly-deleted ones (the executor member is non-assignable).
constexpr decltype(auto) operator=(wrapper cv_ref other);  // × 8

// Assignment from any other operand: a plain value or a different wrapper type
// (read through its own executor, so the value types may differ).
// Generated by SCL_WRAPPER_ASSIGNMENT_FOR_OPERAND; constrained out for the
// wrapper's own type (handled above).
template <typename Other>
constexpr decltype(auto) operator=(Other && other);
```

- **Any operand is accepted** — a plain value (`w = 42`), another wrapper, or the
  same wrapper type. This is why `w = value` works, matching every other reflected
  operator.
- **Fundamental and class value types alike** — the value path uses the expression
  `access(self) = source` (not `.operator=()`), so it assigns `int`, `double`, and
  classes with a member `operator=` equally. (Unlike the compound assignments
  `+=`, `*=`, …, which are reflected via the value's member operator and are
  therefore unavailable for fundamental value types.)
- **Return type** — `decltype(auto)`, like every reflected operator: the executor
  override's return type on the override path, or the result of `access(self) = source`
  (typically `value_type &`) on the value path. Not necessarily `*this`.
- **Constraint / `noexcept`** — each overload is constrained on the wrapped value
  being assignable from the resolved operand, and propagates the `noexcept` of the
  selected path. A wrapper over a non-assignable value type exposes no assignment.
- **Incomplete-type note** — the self-type overloads are non-template, so their
  constraints are evaluated while the wrapper is still incomplete; they resolve the
  source's value through its executor (`executor_type::access`) rather than through
  the wrapper.

## Executor access

The executor member is private; access is provided through
`scl::feature::detail::executor_access::get(w)` and via the
`scl::feature::executor_trait<wrapper<V,E>>` specialisation used by
`SCL_REFLECT_METHOD`.

## Examples

### Basic usage

```cpp
#include <scl/feature/wrapper.h>
#include <scl/feature/executor/inplace/plain.h>

using IntWrapper = scl::wrapper<int, scl::feature::inplace::plain>;

IntWrapper w{42};
// Access the held value through the executor:
int & v = scl::feature::inplace::plain<int>::access(
    scl::feature::detail::executor_access::get(w));
```

### With reflection

```cpp
#include <scl/feature/wrapper.h>
#include <scl/feature/reflection/method.h>
#include <scl/feature/executor/inplace/plain.h>

struct Counter {
    int value() const & { return m_value; }
    void increment()    { ++m_value; }
private:
    int m_value = 0;
};

template <typename Wrapper, typename Executor>
class scl::feature::reflect<Wrapper, Executor, Counter>
{
    SCL_REFLECT_TYPE(Wrapper, Executor)
    SCL_REFLECT_METHOD(value)
    SCL_REFLECT_METHOD(increment)
};

using CounterWrapper = scl::wrapper<Counter, scl::feature::inplace::plain>;

CounterWrapper c;
c.increment();
c.increment();
int v = c.value();  // 2
```

### Nested wrappers

```cpp
// Outer: plain (no overhead). Inner: a locking executor.
using Inner = scl::wrapper<int, locking_executor>;
using Outer = scl::wrapper<Inner, scl::feature::inplace::plain>;

Outer w{42};
// wrapper_cast unwraps to int through both layers:
int val = scl::wrapper_cast(w);
```
